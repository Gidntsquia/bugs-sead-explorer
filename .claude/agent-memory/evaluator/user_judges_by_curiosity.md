Jaxon (not a domain expert) rejected round 1 of the BugsCEP+SEAD explorer (2026-09-27) even though every data check matched: "lacks focus and doesn't inspire curiosity", "needs to simplify things for me, and make it easier to do things with the data".

Round 2 (same day) was also rejected. The worker only trimmed text and collapsed sections. Jaxon said: "App is basically unchanged. I want a redesign with the frontend-design plugin. I want the app to just be the data and none of this extra fluff". About the offline/SEAD-unreachable message: "I dont see it and I dont care about that feature".

**How to apply:** In evals, correct numbers aren't enough, and small trims read as "unchanged". Put the user-judged "does it make sense / is it engaging" questions first. Don't spend his attention on the offline mode. Treat a visible redesign as the bar.

Round 3 (same day, real redesign: map-first, sidebar, no home page) was accepted on redesign / just-data / simpler. He was fine with a few multi-sentence captions left in. Curiosity was still not met: "Not quite yet. Im not sure what is missing, though. Maybe some way to analyze the data?" So once the look is right, the next gap is analysis, not more trimming.

Round 4 (2026-09-28: Analyze page with filter/time/habitat-mix tabs, a Three.js 3D fly-through and a public repo) was accepted on every user question, including curiosity and understanding. Adding real analysis and a 3D view was what closed the gap.
